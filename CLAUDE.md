This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

FlareLens is a SaaS platform that monitors Cloudflare usage and detects anomalies to protect users from unexpected bills. It's a **pnpm monorepo** with two deployed Cloudflare Workers: a Hono API and a SvelteKit frontend.

## Working Standards

- **Production quality only.** This is not an MVP. Every feature must be implemented to a production-ready standard — no shortcuts, no stubs.
- **Complete every task fully.** Never leave TODOs, placeholders, or "left as an exercise." If something is in scope, finish it.
- **Use the Cloudflare MCP.** A Cloudflare MCP server is available — always use it when interacting with Cloudflare resources (Workers, D1, KV, R2, queues, etc.) instead of guessing or using wrangler CLI manually. Always use account ID `__CLOUDFLARE_ACCOUNT_ID__` for all Cloudflare MCP calls.

## Commands

All commands are run from the repo root unless noted otherwise.

```bash
# Development (runs all apps in parallel)
pnpm dev

# Build all workspaces
pnpm build

# Type-check all workspaces
pnpm check

# Lint all workspaces
pnpm lint

# Test all workspaces
pnpm test

# Run a single workspace's script
pnpm --filter api dev
pnpm --filter web dev

# Deploy (from app directory)
cd apps/api && pnpm deploy
cd apps/web && pnpm deploy

# Regenerate Cloudflare Worker types
cd apps/api && pnpm cf-typegen
cd apps/web && pnpm cf-typegen
```

## Architecture

### Stack
- **Frontend** (`apps/web`): SvelteKit 5 + Svelte 5 runes + Tailwind CSS 4 → deployed as Cloudflare Worker via `@sveltejs/adapter-cloudflare`
- **Backend** (`apps/api`): Hono 4 with JSX renderer → Cloudflare Worker
- **Database**: Cloudflare D1 (SQLite), KV, R2, Analytics Engine, Queues, Durable Objects (planned)
- **Validation**: Zod 4

### Monorepo layout
```
apps/
  api/          # Hono API Worker (src/index.tsx is entry point)
  web/          # SvelteKit app
packages/
  config/       # (empty — placeholder)
  db/           # (empty — placeholder)
  shared/       # (empty — placeholder)
  ui/           # (empty — placeholder)
dev_docs/       # Product and technical architecture docs
tsconfig.base.json  # Shared TS config (ES2022, Bundler resolution, strict)
```

### Web app route groups
- `(public)/` — Public/marketing pages
- `(auth)/` — Login, register, forgot-password
- `(app)/` — Protected dashboard routes (dashboard, anomalies, analytics, rules, notifications, billing, integrations, inventory, team, mitigations, audit, developer, settings)
- `onboarding/` — Multi-step setup wizard (connect → zones → success)

### Frontend data layer
Currently all dashboard data comes from static mock data in `apps/web/src/lib/data/mock.ts`. The app is not yet wired to any live API.

### Key layout components
- `AppShell.svelte` — Responsive shell with fixed sidebar (desktop) / drawer (mobile)
- `Sidebar.svelte` — Navigation with active state from `$page`
- `TopBar.svelte` — Header with search and user controls

### API entry point
`apps/api/src/index.tsx` — Hono app with JSX renderer configured (`jsxImportSource: hono/jsx`).

### Cloudflare config
Each app has a `wrangler.jsonc` with its own Worker name, compatibility date, and bindings. Run `pnpm cf-typegen` inside an app after changing `wrangler.jsonc` to regenerate `worker-configuration.d.ts`.

### TypeScript
All packages extend `tsconfig.base.json`. The web app's `tsconfig.json` extends `.svelte-kit/tsconfig.json` (auto-generated by SvelteKit).
