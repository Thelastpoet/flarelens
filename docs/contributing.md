# Contributing

We welcome contributions of all kinds! Whether you're fixing a bug, adding a feature, or improving documentation, your help is appreciated.

## Getting Involved

- **Join the community:** Join the discussion on [GitHub Discussions](https://github.com/flarelens/flarelens/discussions) to discuss ideas and get help.
- **Reporting bugs:** If you find a bug, please open an issue on GitHub with a clear description and reproduction steps.
- **Submitting features:** We recommend opening an issue to discuss new features before starting development.

## Development Workflow

1. **Fork the Repository:** Create your own fork of the FlareLens repository.
2. **Create a Branch:** Use a descriptive branch name (e.g., `fix/rate-limit-bug` or `feat/new-alert-channel`).
3. **Set Up Local Development:** Refer to the [Getting Started](./getting-started.md) guide.
4. **Follow Coding Standards:**
   - Use `pnpm lint` and `pnpm check` to ensure your code follows our standards.
   - We use Biome for linting and formatting.
   - Ensure all tests pass with `pnpm test`.
5. **Commit Your Changes:** Use clear and concise commit messages.

## Submitting a Pull Request

1. **Push to Your Fork:** Push your branch to your forked repository.
2. **Open a Pull Request:** Create a PR on the main FlareLens repository.
3. **Describe Your Changes:** Provide a clear summary of your work and any relevant issue numbers.
4. **Code Review:** A maintainer will review your PR and may suggest changes.
5. **Merge:** Once approved, your PR will be merged into the main branch.

## Documentation

We value good documentation! If you're adding or changing functionality, please update the relevant documentation files in the `docs/` directory.

## Testing

New features should include tests to ensure they work as expected and to prevent regressions. Check the `test/` directories in each application for examples.
